# Design changelog: `claude-dash`

Append-only. One entry per design change, most recent first. A code change with no corresponding entry here, when it should have one, is the specific failure this file exists to catch on review.

| Date | Concept(s) affected | Change | Why |
| --- | --- | --- | --- |
| `2026-11-16` | session-discovery, prompt-delivery, session-closing | A session counts as live only when `ps` names its pid's command and that command is `claude`, and only the newest registry entry for a session id is returned. Prompt delivery and closing resolve a session id through that same rule instead of taking the first registry file that matched. Session discovery gains criteria 3 to 5, prompt delivery criteria 8 and 9. | Signal 0 only proves some signalable process holds the pid. A registry entry from 18-09-2026 whose pid had been reused by Terminal.app was reported as a live idle session; it shared a session id with a genuinely live session, so the dashboard (which keys cards by session id) showed one card for two sessions and hid the real one, and a reply addressed to that session resolved to the stale entry, was refused for having no terminal, and never arrived. |
| `2026-11-16` | session-closing (new), http-api, dashboard-ui | Added session closing: a close button on each live card stops the session's `claude` process (SIGTERM, SIGKILL after 5 s) and closes its Terminal window once only the shell is left. Sessions that are not idle need confirmation, enforced by the server. The HTTP API gains `POST /api/sessions/<id>/close` under the same origin checks as the prompt route; the closed column opens after a close. | Tabs were being kept open only because closing them felt risky; the transcript survives a close and the closed column offers the resume command. |
| `2026-11-16` | prompt-delivery (new), http-api, dashboard-ui | Added prompt delivery: a reply typed on a card is typed into the session's Terminal tab, found by tty, and submitted. The HTTP API gains `POST /api/sessions/<id>/prompt`, restricted to requests from the dashboard's own origin; its "read only" decision is narrowed to every other route. Dashboard cards for waiting and idle sessions gain a reply composer that survives refreshes. | Answering a waiting session meant finding its tab among a dozen. Terminal delivery chosen over Claude Code's peer socket because typed text is recorded as the user's own prompt. |
| `2026-11-16` | dashboard-ui | Sessions laid out as columns (waiting on you, working, idle, plus closed when ticked) instead of stacked groups; one swipeable column at a time at 720 px and narrower, with a tab strip; cards keyed by session id so an expanded last reply survives a refresh. Criteria 1 to 7 added or rewritten. | Groups stacked as rows made state changes hard to follow and were unusable on a phone, and every 5-second refresh collapsed an expanded last reply. |
| `2026-11-16` | all | Design folder created. Eight concepts, the coordination map and acceptance criteria written to match the code at commit `b2ffa76`. No automated tests exist; each concept lists that under "Known implementation gaps". The permission-prompt interaction in attention classification is recorded as `designed`. | Start the design-first workflow so later changes are made against a written design. |
