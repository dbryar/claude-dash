# Design changelog: `claude-dash`

Append-only. One entry per design change, most recent first. A code change with no corresponding entry here, when it should have one, is the specific failure this file exists to catch on review.

| Date | Concept(s) affected | Change | Why |
| --- | --- | --- | --- |
| `2026-11-25` | session-view (new), dashboard-ui | Added the session view. An "open" button on every card, and a "show full reply" link under a cut-off last reply, open one session as a modal dialog (full screen at 720 px and narrower). It shows the whole last reply in a scrolling area, plus the full last prompt and away summary. The card's own composer and question form move into the view and back, so a draft is never in two places, and the reply box grows up to 40 % of the view. No server change: `/api/sessions` already carries the full `lastAssistant`. Only the card cut it short. | A long last reply was cut to its final 3,000 characters on the card, and the reply box was a few lines high, so reading or answering a long reply meant going back to the terminal. |
| `2026-11-25` | prompt-delivery, attention-classification, dashboard-ui | A session with registry status `shell` can now be replied to: `canReply` is true for `idle` or `shell`, delivery accepts both (prompt-delivery criteria 10 and 10a corrected, 10b added), and the card says "background task running" instead of "status shell" (dashboard-ui 14a). Attention classification records `shell` as idle by design rather than as an approximation. | `shell` was treated as an unknown state that could not take a reply, so a session sitting at its prompt lost its reply button whenever it had a background task running: this design's own session did, for the whole time it waited on the user, because the emulator and a recorder were running in the background. Reading the 2.1.331 binary showed `shell` is written only in place of `idle`, when a background bash task the session started is unfinished. The input box is open, so the refusal was wrong. |
| `2026-11-24` | session-starting, configuration, http-api, dashboard-ui | Session starting can resume a recently closed session (`claude --resume <id>` in the directory its transcript records, refused while it is still running), and starts every session in a chosen permission mode: `skip` (`--dangerously-skip-permissions`), `auto` (`--permission-mode auto`) or `ask` (no flag). The default is `SESSION_BOARD_PERMISSION_MODE`, `auto` when unset; the form's choice is remembered in the browser. Closed cards gain a resume button that opens the form with the session picked. The front-application restore is now done only on the Cmd-T route, once, because on the merged-tab route the restore watcher was what brought Terminal forward. | A session started with plain `claude` asked for approval on every tool call, and a closed session could only be brought back by copying the resume command into a tab by hand. Two starts in a row left Terminal in front. |
| `2026-11-24` | session-starting | A started session's tab now opens behind: the previously selected Terminal tab is selected again, and if Terminal comes to the front the previously frontmost application is brought back (read with `lsappinfo`, restored with `open -b`, so no permission is asked). Criterion 4a added. | Each new tab was selected as it opened and took the keyboard input you were typing into another tab. |
| `2026-11-24` | session-starting (new), http-api, dashboard-ui | Added session starting. A "new session" button in the header takes a directory (suggested from live and closed sessions) and `POST /api/sessions/new` types `cd <quoted directory> && claude` into a new tab of the frontmost Terminal window. When macOS prefers tabs always, `do script` already opens a tab; otherwise Cmd-T is pressed through System Events and the new tab is recognised by its new tty. If no tab appears, a new window is opened instead and the response says so. The route sits under the same origin checks as the other write routes. | Starting work meant leaving the board for Terminal, opening a tab and changing directory by hand. Terminal's scripting dictionary cannot make a tab, so the key press is the only way to get one; the new-tty check stops the command landing in a tab already in use, and a tab count cannot, because Terminal's dictionary lists each native tab as a window of its own. |
| `2026-11-18` | question-answering (new), http-api, dashboard-ui | Added question answering. For a session waiting on input, the server reads the question menu from its Terminal tab and adds it to `/api/sessions` as `menu`; the card shows it as a form, one page at a time; `POST /api/sessions/<id>/answer` checks the screen still shows that page, then sends arrow keys and Enter one step at a time, re-reading the screen before each. The menu's key behaviour, and the fact that an open question is not in the transcript, were measured on a throwaway session and are recorded in the concept. | A session stopped at a question could be seen on the board but still had to be answered in its tab. |
| `2026-11-18` | attention-classification, session-discovery, dashboard-ui | Sessions whose registry status is `waiting` (Claude Code 2.1.327 and later) are labelled `asked you`, and discovery passes `waitingFor` through so the card can say what the session is waiting for. | A session stopped at a question showed as idle, the one state the board exists to surface. Claude Code now records this state itself, which is stronger than any text rule. |
| `2026-11-18` | attention-classification, dashboard-ui | "Asked you" now reads the whole last paragraph of the last reply for a question or a listed request phrase, not just a trailing `?`. The last reply renders as Markdown, with a header toggle back to raw text. The away summary moves from the card body to a hover hint on the title. | No session had shown as waiting on you for a day, because replies that need you usually end with a statement. Raw Markdown in a fixed-width font was hard to read, and the away summary made every card longer. |
| `2026-11-16` | session-discovery, session-closing, prompt-delivery, transcript-digest, attention-classification | Session identity is now checked against `procStart`, the process start time the registry records, instead of requiring the process to be named `claude`. The process name is kept only as a fallback for an entry with no usable `procStart`, and an identity that cannot be determined is treated as live. Session discovery criteria 3 to 5 rewritten and the list renumbered; session closing criterion 5 and prompt delivery criterion 8 follow it. Version divergences re-measured against 2.1.325. | The name test was wrong: Claude Code rewrites its own process name, so a background job reports `claude bg-spare` and `ps -o ucomm=` reports the version string. Requiring the name to be `claude` hid a real background session from the board and would have refused to close it — a defect introduced by the previous entry and found by upgrading from 2.1.220 to 2.1.325. `procStart` is exact and name-independent: measured across five entries, the four holding their own process agreed to the second and the reused pid was out by 29 days. |
| `2026-11-16` | prompt-delivery, dashboard-ui, attention-classification, session-discovery | Whether a session can be replied to is now owned by prompt delivery and published per session as `canReply`, true only when the registry status is exactly `idle`. The composer follows that field instead of the card's column (dashboard-ui criterion 14 rewritten, 14a added; prompt-delivery criterion 10a added). A card whose status is neither `idle` nor `busy` shows that status. | A `shell` session is labelled idle, so the page offered a reply box that delivery then refused as busy. Deriving the affordance from the label meant the page could always promise something the server would refuse; deriving it from the server's own condition removes the class of defect rather than the one instance. |
| `2026-11-16` | transcript-digest, dashboard-ui, attention-classification | Documentation only, no behaviour change. Recorded that every transcript record this design reads is optional and that an absent field is omitted rather than defaulted (transcript-digest criterion 3, dashboard-ui criterion 5). Corrected attention classification's claim that the registry has only `idle` and `busy`, added criterion 2a for an unrecognised status, and recorded the `shell` status as a known defect. Added a version-divergence table to the design index. | Two of this design's assumptions about Claude Code's internal files are false on 2.1.220: `cost-state` records are never written, so no card shows a cost, and a third registry status `shell` exists, which is labelled idle and offers a reply button that delivery always refuses. The design claimed otherwise, so the design was wrong before the code was. |
| `2026-11-16` | configuration | The default ticket pattern now skips a stop list of prefixes that are not ticket systems (`SHA`, `UTF`, `ISO`, `RFC`, `CVE` and similar). An explicit `TICKET_PREFIXES` turns the stop list off. Criterion 3 corrected, criterion 4 added. | `SHA-256` was shown as a ticket key on two cards. The old criterion 3 permitted it, so the criterion was wrong, not just the code: ordinary technical writing is full of Jira-shaped strings. |
| `2026-11-16` | session-discovery, prompt-delivery, session-closing | A session counts as live only when `ps` names its pid's command and that command is `claude`, and only the newest registry entry for a session id is returned. Prompt delivery and closing resolve a session id through that same rule instead of taking the first registry file that matched. Session discovery gains criteria 3 to 5, prompt delivery criteria 8 and 9. | Signal 0 only proves some signalable process holds the pid. A registry entry from 18-09-2026 whose pid had been reused by Terminal.app was reported as a live idle session; it shared a session id with a genuinely live session, so the dashboard (which keys cards by session id) showed one card for two sessions and hid the real one, and a reply addressed to that session resolved to the stale entry, was refused for having no terminal, and never arrived. |
| `2026-11-16` | session-closing (new), http-api, dashboard-ui | Added session closing: a close button on each live card stops the session's `claude` process (SIGTERM, SIGKILL after 5 s) and closes its Terminal window once only the shell is left. Sessions that are not idle need confirmation, enforced by the server. The HTTP API gains `POST /api/sessions/<id>/close` under the same origin checks as the prompt route; the closed column opens after a close. | Tabs were being kept open only because closing them felt risky; the transcript survives a close and the closed column offers the resume command. |
| `2026-11-16` | prompt-delivery (new), http-api, dashboard-ui | Added prompt delivery: a reply typed on a card is typed into the session's Terminal tab, found by tty, and submitted. The HTTP API gains `POST /api/sessions/<id>/prompt`, restricted to requests from the dashboard's own origin; its "read only" decision is narrowed to every other route. Dashboard cards for waiting and idle sessions gain a reply composer that survives refreshes. | Answering a waiting session meant finding its tab among a dozen. Terminal delivery chosen over Claude Code's peer socket because typed text is recorded as the user's own prompt. |
| `2026-11-16` | dashboard-ui | Sessions laid out as columns (waiting on you, working, idle, plus closed when ticked) instead of stacked groups; one swipeable column at a time at 720 px and narrower, with a tab strip; cards keyed by session id so an expanded last reply survives a refresh. Criteria 1 to 7 added or rewritten. | Groups stacked as rows made state changes hard to follow and were unusable on a phone, and every 5-second refresh collapsed an expanded last reply. |
| `2026-11-16` | all | Design folder created. Eight concepts, the coordination map and acceptance criteria written to match the code at commit `b2ffa76`. No automated tests exist; each concept lists that under "Known implementation gaps". The permission-prompt interaction in attention classification is recorded as `designed`. | Start the design-first workflow so later changes are made against a written design. |
